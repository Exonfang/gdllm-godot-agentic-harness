# Security policy

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion,
pull request, benchmark transcript, or chat log. Use GitHub's private
vulnerability-reporting flow when it is available. If it is not available,
contact the repository owner privately through a contact method published on
their GitHub profile and include only enough detail to establish a secure
follow-up channel.

Useful reports state the affected version and platform, the trust boundary that
was crossed, the minimum reproduction, and the expected impact. Remove API
keys, OAuth tokens, session contents, private project files, absolute user
paths, and other personal data. Synthetic credentials and a disposable Godot
project are preferred.

Please allow the maintainer time to reproduce and prepare a coordinated fix
before publishing technical details. Acknowledgement, remediation timelines,
and release or advisory decisions remain with the maintainer.

## Supported versions

Security fixes are expected to target the current release line. Older releases
may not receive a backport; users should upgrade to the newest patched release.
